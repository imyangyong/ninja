# 语境解码

把表达当作语境中的信号来解码，而不是只给字典释义。目标是让用户能把解释替换回原话，并知道说话者实际在表达什么。

## 解码流程

1. 锁定原词及其所在句子。上下文不足但不影响核心理解时，给出最常见解释并标注适用语境；只有不同解释会显著改变结论时，才询问来源、完整原句或场景。
2. 判断表达类型：缩写、专业术语、外来词、中英混用、网络梗、隐喻、委婉说法或带立场的话术。遇到新近流行、圈内自造或无法可靠识别的表达时，搜索原句或明确说明不确定，不根据字面硬猜。
3. 逐层解码：
   - 先用一句最直白的中文给出此处实际含义。
   - 必要时解释全称、字面来源或形成方式；这些内容服务于理解，不写成词源考据。
   - 放回原语境，说明它对应的具体动作、状态、要求或判断。
   - 存在言外之意时，区分“原话明确表达”和“根据语境推断”，并标明推断把握。
   - 给一个贴近同类场景的例子。用户可能需要接话、确认或拒绝时，再给一句自然回应。
4. 做替换测试：将“一句话解释”替换回原句。替换后仍自然且意思一致，才完成解码；否则继续收窄含义。

## 回答格式

按问题复杂度裁剪以下结构。简单词语不为凑格式扩写；多义、话术或强语境表达保留相关栏目。

```text
一句话：这里的 X 就是……

拆开看：……
放回这句话：……
言外之意：……（仅在确有隐含信息时）

例子：……
你可以这样回应：……（仅在用户可能需要接话时）
还可能指：……（仅在存在会改变理解的常见义项时）
```

## 解码准则

- 优先解释“这里是什么意思”，再补充“通常是什么意思”。
- 使用比原词更朴素的中文；不要用另一组黑话解释黑话。
- 缩写有多个展开方式时，根据领域排序，不把猜测写成唯一答案。
- 中英混用按实际用法解释，不假设它符合标准英文。例如，职场里的 `DDL` 通常就是“截止时间”，重点是何时必须交付。
- 对话术同时说明信息层和关系层：对方说了什么，以及这句话可能在施加什么预期、压力或边界。
- 不自动把普通表达解读成操控或恶意；证据不足时给出中性解释，并将更强判断标为可能性。
- 保留行业差异。例如，`fixed point` 在数学中是“不动点”，在代码审查中也可能指用来比较变更的固定基准。

当每个影响理解的词都已说明、确定含义与语境推断已分开，且替换测试通过时结束。
