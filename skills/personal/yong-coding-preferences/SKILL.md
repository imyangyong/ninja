# Yong 编码偏好

把以下偏好作为编码基线。用户对当前任务的明确要求和仓库内已有约定优先；在两者未规定时应用本 Skill。

## 执行流程

1. 先检查受影响文件及项目配置，识别使用的框架、原子化 CSS 工具和既有写法。
2. 只应用与本次改动相关的偏好，并保持未涉及代码稳定。
3. 完成后逐项检查所有新增或实质修改的代码；每条适用偏好均已落实或有项目约束作为例外。

## Vue Template

在页面级 Vue 组件的 `<template>` 中，按页面布局模块添加含义注释。

- 在每个主要模块的根节点前添加注释，例如页面头部、搜索条件、数据列表、详情区、侧栏、分页区。
- 注释表达模块的业务或布局含义，并沿用文件已有的注释语言和格式。
- 注释保持在模块粒度；一个注释覆盖其完整模块。
- 新增或实质修改页面布局时，同步补齐改动范围内的模块注释。

```vue
<template>
  <main>
    <!-- 搜索条件 -->
    <section>
      <!-- ... -->
    </section>

    <!-- 用户列表 -->
    <section>
      <!-- ... -->
    </section>
  </main>
</template>
```

## 原子化 CSS

项目已配置原子化 CSS 时，优先使用项目支持的 Attributify Mode。

- 从依赖和配置文件确认 Attributify Mode 是否可用，并沿用项目现有语法。
- 对可直接表达的静态原子样式优先使用属性化写法。
- 动态 class、组件传入的 class、项目自定义 class，以及当前工具无法属性化表达的样式，沿用合适的 class 写法。
- 仅整理本次新增或实质修改的样式；保持无关代码稳定。

```vue
<div flex="~ col" items-center gap-4 p-4>
  <!-- ... -->
</div>
```

## 完成标准

- 每个新增或实质修改的 Vue 页面布局模块都有清晰的模块含义注释。
- 每组新增或实质修改的原子化样式都已优先采用项目可用的 Attributify 写法。
- 代码符合项目现有格式化、类型检查和测试要求。
